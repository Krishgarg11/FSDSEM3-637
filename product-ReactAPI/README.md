# Product Manager — React + Express API

A small full-stack product management app:

- **Backend** — Express REST API in `index.js` with full CRUD (GET, POST, PUT, PATCH, DELETE) and JSON file storage in `products.json`.
- **Frontend** — Vite + React app that lists products, adds new ones, edits and deletes them, and filters the list by name or category.

## Project structure

```
product-ReactAPI/
├── index.js                  # Express API (port 4000)
├── products.json             # Product "database"
├── test-api.js               # API test suite (node --test style asserts)
├── requests.http             # Ready-to-run REST Client requests
├── index.html                # Vite entry page
├── vite.config.js
└── src/
    ├── main.jsx              # React entry point
    ├── App.jsx               # Screen layout + data loading + CRUD actions
    ├── App.css               # App specific styles
    ├── index.css             # Base styles / theme tokens
    ├── api/products.js       # fetch helpers for the Express API
    └── components/
        ├── ProductForm.jsx   # Add / edit form with validation
        └── ProductList.jsx   # Product table with edit + delete buttons
```

## Getting started

```bash
npm install        # install dependencies

npm start          # terminal 1 -> API on http://localhost:4000
npm run dev        # terminal 2 -> React app on http://localhost:5173
```

Open the Vite URL in the browser. In another terminal, while the API is running you can
check every endpoint with:

```bash
npm test           # runs test-api.js against http://localhost:4000
```

## API endpoints

| Method | Route               | Description                          |
| ------ | ------------------- | ------------------------------------ |
| GET    | `/`                 | API info and endpoint list            |
| GET    | `/products`         | All products                         |
| GET    | `/products/:id`     | One product (400 invalid id, 404 missing) |
| POST   | `/products`         | Create a product (201 on success)    |
| PUT    | `/products/:id`     | Replace every field of a product     |
| PATCH  | `/products/:id`     | Update only the fields that are sent |
| DELETE | `/products/:id`     | Delete a product                     |

### Product schema

```json
{
  "id": 1,
  "name": "Wireless Keyboard",
  "category": "Electronics",
  "price": 1499,
  "stock": 25
}
```

Rules enforced by the API:

- `name` and `category` must be non-empty strings
- `price` must be a number greater than or equal to 0
- `stock` must be a whole number greater than or equal to 0
- `PUT` needs all four fields, `PATCH` accepts one or more of them
- ids are generated by the server (`max(id) + 1`)

## Frontend features

- Loads products from the API on start, with loading, empty and error states
- Add form (`POST`) that resets after a successful save
- Edit form (`PUT`) pre-filled from the selected row, with a working **Cancel** button
- Delete (`DELETE`) with a confirmation prompt
- Search box and category dropdown that filter the table instantly
- Summary cards: total products, inventory value, and low-stock count
- Stock is highlighted when it is low (5 or less) or out of stock

## Environment variable

The frontend reads the API URL from `VITE_API_URL` and falls back to
`http://localhost:4000`. Create a `.env` file to point it somewhere else:

```
VITE_API_URL=http://localhost:4000
```

The API itself accepts a `PORT` environment variable (default `4000`) and enables CORS so
the Vite dev server can call it.
